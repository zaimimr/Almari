# Live Studio photograph review

Initial batch, 11 October 2026, after explicit approval for the 20 prepared requests. All 20 were attempted once against the configured live service: 17 returned decodable 1024-by-1024 images and three returned HTTP 502. No retries, deployment or provider change were performed in that batch. This is one batch on one service, not a provider comparison or an acceptance-rate estimate.

The user accepted the nine results initially marked for owner review and confirmed the eight failures. Final batch result: nine accepted images, eight rejected images and three HTTP errors. The initial crop evaluation had 12 failures among 56 extended variants. The current [crop report](native-photos.md) records all ten originals and all 56 variants passing; that result does not establish Studio fidelity.

## Input dimension recovery

The later 20-case run on deployment `31a07d09-455b-44b6-b82c-4b1e37eed137` returned 17 images and the same three fragment failures. A live Worker log identified `AiError: 3030: Invalid input image[0]: Image width must be at least 64 pixels and height at least 64 pixels`. The three inputs measured 34-by-150 (teal scarf), 72-by-54 (floor trousers) and 62-by-150 (floor jacket). These errors were input validation failures, not transient outages or content rejections.

Native and web preparation now centre references on white padding when either side is below 64, preserving fabric scale and proportions. Worker validation rejects known undersized dimensions before inference. The evaluation harness applies the same padding, records failure latency and continues through failed cases. The Worker still bounds retries for transient provider failures.

Deployment `542fc502-cffc-471e-b0f7-ebd067d3f5c1` uses the same Klein 4B model. All three padded fragments returned HTTP 200 and decodable 1024-by-1024 images: floor trousers in 8.4 seconds, floor jacket in 8.5 seconds and teal scarf in 14.2 seconds. Local records and comparisons are under `planning/build/studio/crop-eval/improvements/padded-recovery/`; the earlier repeated batch is under `deployed-recovery-20261011/`. Paid evaluations remain authorized by the user.

This verifies recovery of these three dimension failures, not overall visual fidelity. The new floor trousers lose their washed texture; the floor jacket changes length and pocket construction. ## Replacement provider

The user ruled out further Gemini and OpenAI use. The next candidate is [Seedream 5 Pro through Cloudflare](https://developers.cloudflare.com/ai/models/bytedance/seedream-5-pro/), using the existing account and AI binding. The Worker adapter preserves both references and the current prompt, requests 1024-by-1024 output without a watermark, validates and bounds the provider image download, and retains the existing retry and quota behavior. Transport tests do not establish garment fidelity.

The first live Seedream request returned HTTP 402, code 2021. The user then funded the existing gateway. The initial fifteen direct-API Seedream images decode as 1024-by-1024 JPEGs. Early responses took 72 to 95 seconds and one 90-second evaluation timed out, so Seedream now uses a shared 180-second Worker budget and the app waits 185 seconds. A timeout does not start another paid generation. Source folding now describes the input scene rather than the final product pose; the revised prompt unfolds trousers successfully. ByteDance's [Seedream examples](https://seed.bytedance.com/en/blog/beyond-generation-it-understands-design-introducing-seedream-5-0-pro) number references from one. The adapter now labels the selection Image 1 and original Image 2, while Klein retains its zero-based multipart labels.


Eight corrected-reference cases returned images: three full garments and five fragments. Hands, hangers and neighboring garments are excluded in these samples, with visibly better coarse jacket fabric and washed denim. The hanging-jacket fragment still invents a large patch pocket, and other reconstructed details and framing remain uncertain. These are improvements, not a fidelity pass. A three-case Seedream 4.5 comparison produces the wrong jacket and an illustrated appearance; a three-case FLUX.2 Max comparison adds unverified pockets and labels. Neither comparison establishes a better production replacement.

The authenticated Seedream version preview returned HTTP 502 despite successful direct API evaluations. A temporary diagnostic Worker confirmed the documented `state`/`result.images` structure and exposed the failure: Workers rejects the Node-supported `fetch` redirect value `error`. The adapter now uses `manual`, rejects non-success responses before reading any image, and never follows a redirect. The real authenticated Worker then returned a valid scarf JPEG in 32.8 seconds. A redirect-rejection regression preserves the download boundary. Further live tests use the actual Worker rather than the REST shim. Unauthenticated requests return 401. Production remains on Klein 4B, version `542fc502-cffc-471e-b0f7-ebd067d3f5c1`, confirmed through the deployments API. The remaining preview batch was stopped after transport failures. The twenty-case actual-Worker comparison is recorded below; garment fidelity and production promotion remain open.

A subsequent four-case actual-Worker trial corrected the scarf’s separate free ends and unfolded the hanging trousers. Its plain reconstructed-panel instruction suppressed visible floor-coat pockets and hardware while still inventing a jacket chest pocket, so that instruction was reverted. Native Seedream selection coordinates now locate the selected fabric in Image 2 using normalized bounding boxes. Both coat fragments then returned decoded 1024-square JPEGs in 32.6 and 35.7 seconds, but the hanging jacket still adds an unverified chest pocket and the floor coat adds unverified cuff straps. This remains a failed fidelity gate. A three-case direct comparison with source originals up to 2048 pixels preserved more floor-coat hardware but still added an unverified jacket pocket. No app input-resolution change was made. A separate compact-prompt comparison returned two coat fragments, with reduced chest-pocket invention but altered floor-coat pocket construction; its scarf attempt failed at the client transport boundary. Neither trial establishes a fidelity pass.

Sanitized request records, actual transport hashes, prompts, inputs and outputs are in `planning/build/studio/crop-eval/improvements/seedream-protocol/`. Its local `review.html` records the earlier corrected-reference comparisons. `worker-matrix-review.html` and `worker-matrix-manifest.json` record the complete twenty-case actual-Worker batch on version `2c8d589c-3a34-4201-b49a-b57c6b251fa2`, all inputs, prompts, hashes and separate recoveries. The first batch returned eighteen decoded 1024-square JPEGs and two client `fetch failed` errors for the hanging trousers. Both separate retries then returned images in 31.2 and 31.0 seconds. These are twenty generated cases across twenty-two attempts, not a twenty-request first-attempt success. Texture and prop exclusion improve, while coat reconstruction and full/fragment construction differences remain open. `decoded-images.json` records decoded dimensions. Additional candidate artifacts and evaluation sources are in `paid-candidates/`.

## Source comparison and correction

A separate three-case source analysis with Anthropic Sonnet 4.6 through the funded Cloudflare account returned observations, but inferred a hood from the hanging jacket’s folded collar. Three comparisons of generated images with their sources caught the unrelated jeans belt yet proposed removing real coat hardware; higher-detail originals reduced some mistakes without making the review reliable. These automatic observations were not added to production or promoted to confirmed owner facts. Their sanitized prompts, hashes and JSON remain under `source-observations/`, `source-comparison/` and `source-comparison-detail/` in the local improvements directory.

A generic second Seedream edit retains the selection and original, adds the draft last, and compares construction against the sources. Direct trials removed unsupported jacket pockets and the jeans belt. The candidate Worker now uses this correction within the existing shared 180-second budget. The draft is never returned when correction fails; the successful-image counter increments once for the final output. Actual Worker version `22332b24-3da0-43d3-aa60-9be5c0d14070` returned the jacket, floor-coat and jeans fragments in 67.4, 70.7 and 65.5 seconds. Fabric improves and the jeans belt is removed; full construction fidelity remains under review. Original-only kameez input also returned a complete garment, but took 172.6 seconds, close to the shared deadline. This is not a production promotion.

Six earlier owner-description requests returned images: kameez hem, hijab end despite a T-shirt guess, trouser waistband despite a shorts guess, blazer sleeve, whole kameez and hijab name alone. Type and arrangement were inspected, while exact details and reconstruction remain part of the fidelity gate. That whole-kameez request sent duplicate references; the later original-only check omitted the duplicate and records one source reference. The new two-stage candidate needs the full real-photo and owner-description matrix before rollout. The actual original-only and name-only checks both succeeded, taking 172.6 and 168.6 seconds. On the subsequent guarded candidate version `aac492d4-c707-40cc-a456-8e4840653994`, a 24-request real-photo/owner-details batch returned only three images before the remaining 21 requests received HTTP 429. A single direct diagnostic request then confirmed HTTP 402, code 2021, insufficient gateway balance. The shared daily counter was 59 against the configured limit of 1000. Testing stopped; these billing failures are not image-quality results. The local `seedream-protocol/correction-review.html` and `correction-manifest.json` preserve all eight decoded results, both candidate versions and the 21 billing failures. Gateway cost-metadata access returned HTTP 403, so actual billed cost remains unmeasured. No account permissions were changed.
