The ordinary HTTP, HTTPS, socket and fetch APIs are disabled by `scripts/tests/no-network.mjs` in `npm run test:offline`. Service tests replace platform/native modules, and Worker tests replace inference with deterministic responses. This guard protects the ordinary test code from accidental network calls; it is not an operating-system network sandbox.

The root development dependencies provide the test runner and Worker types, so checking the app does not require a separate Worker installation. Install the root lockfile with `npm ci` before using the commands below.

## Reproduce without inference

```sh
npm run check
npm run test:offline -- --coverage
npm run test:vision
npm run test:photos
npm run test:photo-gaps
npm run test:photo-variants
node --import=./scripts/tests/no-network.mjs --import=tsx scripts/studio-eval.ts
node --import=./scripts/tests/no-network.mjs --import=tsx scripts/studio-eval.ts --photos
DEVICE='Almari Systems QA' bash scripts/e2e.sh .maestro/system
```

`test:vision` and `test:photos` need macOS/Xcode; the photo suite also needs the packaged parser and three SAM model resources. The preview needs ImageMagick. Simulator tests need a compatible installed iOS runtime and Maestro. The default Studio preview writes to ignored `planning/build/studio/crop-eval/preview/`, separately from historical outputs. The real-photo preview additionally needs the local floor source described in [native photographs](native-photos.md). Only the explicit `--live` flag permits hosted inference.

## What these results cannot establish

The crop matrix represents ten scene types with synthetic image headers and owner descriptions. It verifies request/prompt behavior, not recognition or reconstruction fidelity. The ten original real-photo selections now pass strict landmarks, including the floor-jacket cord and neighbor exclusions. All 56 expanded variants pass unchanged strict assertions. Their [evidence and limits](native-photos.md) include previously repaired cap/blazer/person defects, unchanged strict exclusions, additional printed-fabric landmarks and raw parser category mismatches. Native input tests verify opaque colours, white cutout backgrounds, genuine openings, shifted/rotated references, top-left crop bounds integer mask/source alignment and the 64-to-500-pixel input limits. These checks cover input preparation, not provider fidelity or file-storage failures. The initial approved 20 real-photo Studio requests returned 17 reviewed outputs and three HTTP 502 failures, documented separately; the user accepted nine outputs and confirmed eight failures. Simulator Studio success copies a fixture image.

Historical catalogue-like scarf, trousers and blazer output pairs were inspected locally. They show recoverable silhouettes and visible shadows, but lack reliable per-output request metadata and do not supply the requested full floor/hanging/head/body corpus. The initial provenance-aware 20-request [visual review](studio-photos.md) now exposes clear failures and uncertain reconstruction; it is not a complete accepted corpus. No claim that every crop can be reconstructed correctly, or that one provider is the most reliable, follows from these results. The [analysis](system-analysis.md) specifies the missing corpus and review criteria.

Physical camera behavior, broad on-device parser accuracy, real share sheets, actual notification delivery, complete large-text/VoiceOver task completion and a single all-green run of the full simulator suite still require separate runtime evidence. Further live comparisons ran under the user's continuing paid-evaluation approval. The same Klein 4B model remains deployed, now with bounded transient recovery and input validation. All three previously failing fragments returned valid images after dimension padding. Gemini and Cloudflare's higher-tier model comparisons returned funding errors and no images. Reconstruction fidelity remains unresolved.
