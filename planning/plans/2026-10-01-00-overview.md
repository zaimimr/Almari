# Labels, capture and stylist: plan overview

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each part plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the eight parts of the approved design, in order, each as its own plan that leaves the app working.

**Architecture:** Pure TypeScript domain functions in `src/domain` hold all rules and data changes and are tested with `node:test` through `tsx`. The local Swift Expo module `modules/closet-vision` does image work on the phone. Screens in `app/` and components in `src/ui` only call domain functions through `src/state/closet.tsx`.

**Tech Stack:** Expo SDK 57, React Native 0.86, expo-router, expo-sqlite KV storage, expo-localization, TypeScript, `tsx --test`, Swift with Vision, Core Image and Core ML, SigLIP 2 base (Core ML, 8-bit), SegFormer B2 clothes parser (Core ML, 8-bit), Apple Foundation Models, Apple WeatherKit, Python 3.12 with `uv` for model scripts, Maestro 2.11 for simulator flows.

**Spec:** [planning/implementation/LABELS-CAPTURE-STYLING.md](../implementation/LABELS-CAPTURE-STYLING.md). Research: [planning/research/STYLING-KNOWLEDGE.md](../research/STYLING-KNOWLEDGE.md).

## Global constraints

- Minimum iOS 26 (her iPhone 16 Pro runs iOS 26). Any API or library that needs iOS 27 is gated with `#available` and has an iOS 26 fallback.
- Polyvore data comes from the public mirrors used by the MIT OutfitTransformer project, for personal use only. Review the licence before any public release.
- English or Norwegian bokmål only. Never the em dash character in code, copy, docs or commits.
- No comments in code of any kind.
- No attribution lines in commits, PRs or files.
- Minimum code that solves the task. Match existing style: 2-space indent, double quotes, Prettier defaults, functional domain code returning new `Closet` objects.
- Never overwrite stored data under an older key. The app writes `closet.v3` from Part 1 onward and reads `closet.v2`, then `closet.v1`, only when no newer key exists.
- Unknown values are never shown as facts. Model output is a proposal until she confirms it, and a confirmed value is never replaced by a later proposal.
- No photo, label text or feedback leaves the phone. The only network call is Apple WeatherKit in Part 5, sending latitude and longitude only. City names are geocoded with MapKit `MKGeocodingRequest` (sends the typed city name only). Needle is not used anywhere.
- App language follows the phone: bokmål (`nb`) when the first preferred locale's language is `nb`, `no` or `nn`, else English. Every new or changed user-facing string goes through `t()` from `src/i18n` from Part 1 onward. Never nynorsk.
- Defaults for Norway: metric units and Celsius. Imperial only when she chooses it.
- Model and provider names never appear in screens or customer copy.
- Every new screen works with larger text and keeps the outfit visible where the existing screens do.
- Verification commands: `npm run check` (typecheck, lint, format check, domain tests), `npx expo-doctor`, `npx expo export --platform ios --platform web`, and `npx expo run:ios` on the "Closet Development" simulator for screen checks. Simulator cannot run Vision background removal; cutout-dependent checks use fixtures.

### Native prepare result

```ts
export type LabelGroup =
  | "kind" | "style" | "length" | "sleeve" | "volume"
  | "pattern" | "scale" | "fabric" | "embellishment";

export type LabelScore = { group: LabelGroup; value: string; score: number };

export type Swatch = { rgb: [number, number, number]; share: number };

export type Quality = {
  sharpness: number;
  brightness: number;
  clipped: ("top" | "bottom" | "left" | "right")[];
  coverage: number | null;
  lightSpread: number | null;
};

export type PreparedGarment = {
  original: string;
  cutout: string | null;
  enhanced: string | null;
  thumbnail: string | null;
  frame: { x: number; y: number; width: number; height: number } | null;
  instances: number;
  labels: LabelScore[];
  palette: Swatch[];
  embedding: string | null;
  quality: Quality | null;
  width: number;
  height: number;
  milliseconds: Record<string, number>;
};
```

Part 1 replaces `kinds` with `labels`. Part 2 adds `palette` and `embedding` and removes `color`. Part 4 adds `enhanced` and `quality`. Until a part adds a field, it is absent from the type. `embedding` is base64 of 768 signed 8-bit values: the L2-normalised image embedding multiplied by `127 / max(|v|)` and rounded. Consumers decode to floats and L2-normalise again before use, so the per-vector scale does not need storing.

`Weather` gains a third variant in Part 5: `{ source: "forecast"; warmth; precipitation; exposure: null; at: string }`. A manual choice on Today wins over the forecast for that local date.

Onboarding maps the hijab answer onto the existing `EverydayStyle.hijab` (`always` to `"always"`, `no` to `"not-needed"`, `sometimes` to `null`) and the coverage answer onto `StyleProfile.coverageLevel`. There is no second hijab field.

`StyleProfile` fields added in Part 5 are filled with `null` by `decodeCloset`; `units` defaults to `"metric"`, `onboarded` to `false` for new installs and `true` for existing closets with owned pieces, and `layout` to `"reasons"`.

A piece field with a value and no entry in `sources` counts as confirmed. Sample pieces count as confirmed fixture data.

`Closet.version` becomes 3 in Part 1. Fields added by later parts are optional on `Piece` or have defaults filled by `decodeCloset`, so no further version bump is needed. `decodeCloset` normalises the legacy occasion `celebration` to `party` from Part 6 onward.

## Review focus

1. Opening the app with existing `closet.v2` data that holds samples, owned pieces, saved looks, a Today session and unfinished import jobs: everything opens unchanged, nothing is lost, and `closet.v2` stays untouched. Pinned by migration tests in Part 1, with a fixture copied from the simulator's real snapshot.
2. A photo where the classifier is unsure about several things at once: she gets one question, never a form. Pinned by a recognition test in Part 1 and an attribute test in Part 2.
3. Her own closet with very few pieces (one hijab, no shoes, no bottoms): Today still explains what is missing instead of failing, under both engines. Pinned by scoring tests in Parts 6 and 7.
4. Feedback spam: tapping Not my style twenty times on one outfit must not flip a rule beyond its limit or blacklist a piece everywhere. Pinned by a taste test in Part 6.
5. A care label that is unreadable, in Norwegian, or only says "Made in Turkey": fields that cannot be read stay empty and nothing is invented. Pinned by care label fixture tests in Part 3.
6. A group photo or a photo with a mirror reflection: only the largest person's clothes become proposals, and she is told when other people were ignored. Pinned by a capture test in Part 4.
7. A selfie in dim or mixed light, or with a hijab covering all hair: the app asks for a retake or marks hair unknown instead of guessing a season. Pinned by a colour analysis test in Part 5.
8. No network or a WeatherKit failure on Today: manual weather still works and the screen says the forecast is unavailable. Pinned by a weather test in Part 5.
